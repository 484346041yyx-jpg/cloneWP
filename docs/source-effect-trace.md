# 原站效果追踪

区块宽度默认按原站实测。每个顶层区块单独判断：外框是否贴边、背景画在哪一层、内层内容是否居中限宽。两者有区别时，各记录对应的 `inline-inset`（宽度、左留白、右留白），在不同断点以实际可用宽度为准；轮播另外测标题区、实际裁切边界和轨道，不能拿单张卡片宽度代替视窗宽度。优先让现有原生容器或内容层承担限宽；组件默认样式可能覆盖自定义宽度，必须在前台和编辑画布实测有效结果。每个大区块仍只有一个顶层容器。不用固定像素作为跨站默认。

新建 preparation v8 默认冻结 `source-effect-trace-v1`。历史任务和已发布页面不迁移。该链路负责本次拥有的正文区块，页眉页脚仍走各自的原生验收。产品数据仍由目标站提供，验收分开判断可见卡片的布局和商品来源。

1. **采集。** 按同宽逐区块看实际页面，从外框、内容关系到交互前/后/复原。先找真实绘制层、裁切边界和改变状态的控件，再选组件。已校验的原始浏览器包保留几何，效果追踪从包中提取 SVG 与文字实占范围的相对位置、活动标签的实际绘制层、横向裁切区内完整卡片数量及边缘预露。滚动轨道不要求使用某个特定轮播库。遇到没自动识别的效果，中心以 `effectProbes` 为每个板块加实际观察：`style`、`attribute`、`detail`、`size`、`relationship` 或 `inline-window`。`factIds` 用浏览器事实 ID；布局节点可用 `<snapshotId>:layout:<layoutId>`。需要测交互后或复原时，用独立快照 ID 加 `effectObservations`（哈希绑定的同源 V2 观察清单），以 `state` 指向本帧实际属性。不能以“默认应当这样”填入数值。缺状态、图层或坐标，记名报在采集阶段。
2. **制作。** 派工包里的 `sourceEffectTrace.rows` 来自中心的原站取证。每项在 `sections[].effectImplementations` 指向现有组件和具体落点：实际原生字段、承载该事实的子组件、源样式绑定，或该组件拥有的局部 CSS 选择器。组件知识用来查默认行为、适用条件和绘制层；同一视觉只让一个层负责。优先复用原生设置和已有结构，原生表达不出再用受限 CSS。只写说明或引用不存在的控件不能通过合并。浏览器原始几何的扩展布局事实只用于效果追踪；样式解析器仍使用正式 SourceFacts 支持的绑定。
3. **验收。** 使用合并清单 `effectTrace` 对照独立来源，前台和 Elementor 实际编辑画布各取 V2 浏览器观察。按同一视口宽高、实际内容视口宽度、DPR 及实际状态逐项配对，验证目标节点属于制作阶段记录的组件。同宽时除了比较内容宽度，还要分别核对左右边缘；同宽但偏左或偏右也不通过。已有截图、点击/触摸、轮播步长、首尾控制、响应式和链接检查继续执行；静态帧不当作互动测试。未知效果由原站观察补充，不能用缺少探针当作通过。人工视觉确认仍要看完整区块。

正式审核证据增加 `effectTrace: { version: 1, pageId, fingerprint, frontend, elementor }`。两组均含 `observation: { path, sha256 }` 及 `bindings: [{ effectId, factIds, stateFactId? }]`；每个效果在两组各出现一次。Elementor 每组另带 `editorFrame: { path, sha256 }`，指向 `{ url, observedAt, html, width, height }`，记录当前 Elementor 外层页面经清理的 iframe DOM 片段和实际 iframe 宽高；该批只放同一画布尺寸的观察。V2 读取要求观察包至少有一个名为 `desktop` 的快照；单一手机尺寸批次可用此兼容标签，配对以实测像素和状态为准。观察清单来自对应前台和实际编辑器内 iframe，保留当前页可校验地址、截图和快照，不写一次性凭据。各观察包须在正式审核时间前一小时内。前台 URL 与正常审核 DOM 一致，Elementor iframe 的 `elementor-preview` 必须是当前页面。采集互动帧时，不复用静态截图冒充已点击；若目标站的分支和原站不同，先报差异或说明明确的工作范围。

CLI 的 `replica_effect_trace` 结果标注 `stage`、`section`、`effectId`、`label`、`code`，渲染偏差还给出前台或 Elementor 及实测值。依提示回到对应阶段；不要先改 CSS 或把没有测量的数据写成通过。
